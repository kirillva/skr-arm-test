# Автотесты АРМ (dev-стенд)

E2E и API-тесты веб-приложения АРМ (`https://skr.it-serv.ru/arm/dev/`) на Playwright + TypeScript.

**Объём v1** (см. `PLAN.md`): авторизация, RBAC-состав интерфейса по ролям, API-контракты.
Функциональные сценарии (таблицы, фильтры, CRUD, отчёты) — следующий этап.

## Установка

```bash
npm install
npx playwright install chromium
cp .env.example .env   # Windows: copy .env.example .env
# заполнить MAIN_LOGIN / MAIN_PASSWORD
```

## Запуск

```bash
npm test              # весь набор
npm run test:auth     # только авторизация (@auth)
npm run test:api      # только API-контракты (@api)
npm run test:rbac     # только RBAC (@rbac)
npm run test:smoke    # дымовой набор (@smoke)
npm run report        # открыть HTML-отчёт
```

Первый полный прогон занимает ~15 минут (RBAC: на каждую роль — логин + маскировка + обход разделов).

## Структура

```
config/env.ts          — чтение .env (BASE_URL, API_URL, MAIN_LOGIN, MAIN_PASSWORD)
config/rbac.matrix.ts  — матрица ролей: навигация/вкладки/закрытые маршруты (единая точка правок)
pages/LoginPage.ts     — Page Object страницы авторизации
fixtures/session.ts    — логин через UI, маскировка, навигация/вкладки, выход
api/rpc.ts             — REST/RPC-хелперы (Token base64(логин:пароль))
tests/auth/            — UI-тесты авторизации
tests/api/             — контракты /auth и rpc/core
tests/rbac/            — состав интерфейса по ролям + известные ограничения
```

## Как это работает

- **Логин только через UI**: приложение не хранит токен в localStorage/cookies, поэтому `storageState`
  не используется; каждая тестовая роль начинает с полного логина `manager`.
- **Маскировка (impersonate)**: из-под `manager` открывается страница пользователя
  `#/admin/userdetail?id=<id>&profile=<profile>`, в блоке «Авторизованные устройства» нажимается
  «Замаскироваться». Работает только для профилей с блоком устройств и верифицированным устройством
  у цели (матрица — `config/rbac.matrix.ts`).
- **Изоляция**: Playwright создаёт новый браузерный контекст на тест — сессии тестов не конфликтуют;
  `workers=1`, т.к. на dev одна основная учётка.
- **Ограничения зафиксированы тестами**: Контролёр (`user`) — веб недоступен (404);
  профили `market`/`provider`/`brigade` — маскировка через UI недоступна (нет блока устройств).

## Покрытие

| Набор | Тесты | Тег |
|---|---|---|
| Авторизация | страница, валидация пустых полей, неверные данные (диалог), успешный вход, показ пароля, редирект без сессии, выход, «Забыли пароль?» | `@auth` |
| API | /auth успех (200+token) / неверные (401) / пустые (401); rpc/core с токеном (200) / без токена (401) | `@api` |
| RBAC | 7 маскируемых ролей: состав навигации + вкладки секций + закрытые маршруты; Контролёр = 404; профили без маски | `@rbac` |

## Как добавить роль

1. Найти пользователя с верифицированным устройством (Администрирование → Пользователи → страница
   пользователя → «Авторизованные устройства»).
2. Дописать объект `RoleSpec` в `config/rbac.matrix.ts` (навигация, вкладки, закрытые маршруты).
3. Прогнать `npm run test:rbac`.

## Отчётность и CI

- HTML-отчёт: `playwright-report/` (`npm run report`); trace, скриншот и видео сохраняются при падениях.
- Конфиг CI-агностичен: в пайплайне достаточно `npm ci && npx playwright install chromium && npm test`.
- `retries=1`, `workers=1` — при параллельных запусках из CI оставьте один исполнитель.
